# Release Evidence — T360-20261014-123151

A-02 part 2 — close the empty-checks vacuous pass and enforce a machine-verified gate inventory.

## Why this item exists

`T360-20261014-183210` closed two demonstrated instances of A-02 and explicitly refused to close
the finding, because a bounded scan finding nothing else is not proof that nothing else exists.
This item removes the third instance and then replaces "we looked" with a control that runs on
every test invocation.

## Instance three, measured

Fourteen of the fifteen checks-based predicates in `scripts/ci-write-full-system-summary.mjs` read:

```js
v.status === 'PASS' && Object.values(v.checks || {}).every(Boolean)
```

`[].every(Boolean)` is `true`. A probe that emitted `status: 'PASS'` with `checks: {}` would have
been accepted by the aggregate gate, and `ci:summary:github:assert` only inspects
`summary.failures.gates` — which would be empty. Only `w3CashPostgres` required a minimum key
count.

## Changes

| File | Change |
| --- | --- |
| `scripts/ci-write-full-system-summary.mjs` | New `allChecksPass(v)` requires **at least one** check and all true; all 14 checks-based predicates use it. `w3CashPostgres` keeps `length >= 10` on top |
| `scripts/lib/gate-inventory.mjs` (new) | Every `scripts/**/*.mjs` emitting `status: 'PASS'` must be mechanically bound to something that can fail the build, via one of six mechanisms proven by **parsing** |
| `tests/gate-inventory.test.mjs` (new) | 4 controls: the repository classifies, each mechanism lights up on its own marker, a rogue emitter is reported, the exemption set is empty and needs a ≥20-char rationale |
| `tests/github-full-system-summary.test.mjs` | Behavioural negative control: six gates fed `status:'PASS'` + matching `sourceIdentity` + `checks:{}` must each report `FAIL`; the same gate with one real check reports `PASS` |
| `config/product-completeness.json` | A-02 → `RUNTIME_VERIFIED` with resolvable evidence |

### The six mechanisms (all verified by parsing, none declared in prose)

| Mechanism | Marker |
| --- | --- |
| `fail-fast-loop` | `Object.entries(checks)` iterated with a `!passed` guard |
| `assert-helper` | three or more `assert(` calls |
| `inline-throws` | three or more `throw` statements |
| `assertion-export` | an exported `assert*`/`verify*`/`require*` function containing a `throw` |
| `workflow-step` | the file or its npm script appears in `.github/workflows/` |
| `aggregate-gate` | the file writes an artifact that `ci-write-full-system-summary.mjs` reads |

Classification is **derived from the files on every run**, so there is no stored registry that can
silently go stale.
